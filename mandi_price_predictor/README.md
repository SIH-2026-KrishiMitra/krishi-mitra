# Mandi Modal Price Predictor

Predicts the future **modal price (₹/quintal)** of an agricultural
commodity in a specific mandi, given:

- State
- District
- Market / Mandi
- Crop / Commodity
- Variety / Grade (optional)
- Prediction date

Built for a Smart India Hackathon demo, structured so the same model +
API layer can be wired straight into a web or mobile app afterwards.

---

## 1. Architecture

```
mandi_price_predictor/
├── data/
│   └── raw_mandi_prices.csv        # historical data (schema below)
├── src/
│   ├── generate_sample_data.py     # synthetic demo data generator
│   ├── features.py                 # feature engineering
│   ├── train_model.py              # trains + evaluates + saves the model
│   └── predict.py                  # inference logic + fallback ladder
├── models/
│   └── price_model.joblib          # trained model + metadata
├── api/
│   ├── app.py                      # FastAPI service (/predict, /metadata)
│   └── demo_frontend.html          # standalone HTML page for the demo
└── requirements.txt
```

**Pipeline:** raw historical CSV → feature engineering → gradient-boosted
tree model → saved model file → FastAPI wrapper → web/mobile frontend.

### Why this model
`sklearn.ensemble.HistGradientBoostingRegressor` is used — it is
functionally equivalent to LightGBM/XGBoost for this kind of tabular
problem, handles high-cardinality categorical columns (State, District,
Market, Commodity, Variety) natively without one-hot encoding, and
trains in seconds on hundreds of thousands of rows. If you have internet
access on your own machine, you can swap in LightGBM by editing only
`build_model()` in `src/train_model.py` — nothing else changes.

### Features used
| Group | Features |
|---|---|
| Identity (categorical) | State, District, Market, Commodity, Variety, Grade |
| Calendar | month, week-of-year, day-of-year encoded as sin/cos (so Dec↔Jan wrap correctly), year (captures inflation trend) |
| Recent history | 7/14/30-day lag prices, 7/30-day rolling mean, 30-day rolling std-dev, all computed **per exact State+District+Market+Commodity+Variety combination** |

The lag/rolling features are what let the model react to real short-term
market dynamics (e.g. a supply glut this month) instead of only
long-run seasonality.

### Fallback ladder (important for a live demo)
Users will often ask for a market/variety combination with little or no
history. `predict.py` degrades gracefully instead of failing:

1. Exact match — State + District + Market + Commodity + Variety
2. Drop Variety — same market, any variety of that commodity
3. Drop Market — district-level history for the commodity
4. Drop District — state-level history for the commodity
5. National — all-India history for the commodity

The API response tells you which tier was used (`match_level`,
`match_note`) so the frontend can show a confidence hint like *"based on
nearby market data"*.

## 2. About the data (⚠️ read this)

This sandbox has no internet access, so `data/raw_mandi_prices.csv` was
generated by `src/generate_sample_data.py` — **synthetic but
realistic** data (trend + seasonality + noise) shaped exactly like the
real government dataset, purely so the full pipeline can be built and
demoed end-to-end.

**For the real hackathon submission, replace it with actual historical
data** from data.gov.in / Agmarknet:

- Dataset: "Variety-wise Daily Market Prices Data of Commodity"
- Browse: https://data.gov.in/resource/variety-wise-daily-market-prices-data-commodity
- API: `https://api.data.gov.in/resource/9ef84268-d588-465a-a308-a864a43d0070?api-key=YOUR_KEY&format=csv&limit=100000`
  (free API key from data.gov.in; paginate with `&offset=`)

As long as the downloaded CSV has these columns, **no code changes are
needed** — just overwrite `data/raw_mandi_prices.csv` and re-run
`train_model.py`:

```
State, District, Market, Commodity, Variety, Grade, Arrival_Date, Min_Price, Max_Price, Modal_Price
```

(This is the exact schema Agmarknet/data.gov.in already publishes.)

## 3. Setup & run

```bash
pip install -r requirements.txt

# 1. (skip if using real data) generate the demo dataset
python src/generate_sample_data.py

# 2. train the model
cd src && python train_model.py && cd ..

# 3. try predictions from the command line
cd src && python predict.py && cd ..

# 4. start the API
cd api && uvicorn app:app --host 0.0.0.0 --port 8000 --reload
```

Then open `api/demo_frontend.html` directly in a browser (point its
"API base URL" field at `http://localhost:8000`), or call the API
directly:

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
        "state": "Maharashtra",
        "district": "Nashik",
        "market": "Lasalgaon Mandi",
        "commodity": "Onion",
        "variety": "Nashik Red",
        "prediction_date": "2025-03-15"
      }'
```

Response:
```json
{
  "predicted_price": 1703.92,
  "unit": "Rs/quintal",
  "match_level": "exact",
  "match_note": "Exact match for state/district/market/commodity/variety.",
  "used_variety": "Nashik Red",
  "used_grade": "Grade I",
  "history_points_used": 511,
  "price_range_hint": {"recent_min": 1525.3, "recent_max": 2687.36}
}
```

`GET /metadata` returns the valid states/districts/markets/commodities/
varieties in the current dataset — use it to populate dropdowns in your
frontend instead of free-text fields (reduces "no exact match" cases).

## 4. Model performance (on synthetic demo data)

Evaluated with a **time-based split** (trained on earlier dates, tested
on the most recent 15% of dates) — a random split would leak future
info through the lag features and overstate accuracy.

| Metric | Value |
|---|---|
| MAE | ₹184.78 / quintal |
| MAPE | 7.04% |
| R² | 0.9815 |

Re-run `train_model.py` after swapping in real data to get real numbers
— accuracy on genuine Agmarknet data will differ (real markets have
sharper shocks — e.g. onion/tomato price spikes — than this synthetic
generator).

## 5. Extending this for the final submission

- **Real-time retraining**: schedule `train_model.py` to re-run weekly
  as new Agmarknet data lands, so lag/rolling features stay current.
- **Weather/rainfall features**: IMD rainfall data by district is a
  strong predictor for crops like onion/tomato — join it in
  `features.py`.
- **Multi-day-ahead forecasts**: currently predicts a single date; to
  show a 7/30-day price trend chart, just call `/predict` in a loop
  over consecutive dates (the API already supports arbitrary future
  dates).
- **Mobile app**: the FastAPI service is framework-agnostic — any
  Flutter/React Native app can call the same `/predict` endpoint.
- **Confidence interval**: `HistGradientBoostingRegressor` supports
  quantile loss — train a second model with
  `loss="quantile", quantile=0.1"` and `0.9` to show a price range,
  not just a point estimate.
